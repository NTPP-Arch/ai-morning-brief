找不齐工具：完整集合成功 21/21，不完整仅 2/39

发生了什么：论文《Completeness and Cost of Retrieval Structures for Multi-Tool Requests in LLM Agents》研究了智能体在调用工具之前，能否先检索到完成任务所需的整套工具。作者比较了词法、稠密检索、查询分解、层级导航、依赖图等检索结构，而不是只看单个工具排得准不准。

关键细节：测试包括带专家依赖标注的 345 个 AppWorld 查询，以及涉及 257 个 MCP 工具的 103 个 MCP-Bench 任务。作者使用 completeness@k：只有所需工具全部进入前 k 个结果，查询才算检索完整。在 AppWorld、k＝16 的设置下，未针对测试集训练且每次查询最多调用一次语言模型的受测结构，完整率都没有超过 10%。一种使用 75 至 90 条域内查询训练的集合级检索器，在两个测试集上的完整率分别达到 .33 和 .58；另一种层级导航方法分别达到 .30 和 .40，但每次查询的语言模型调用次数中位数为 31 至 38，耗时约五分钟。下游检查中，工具集完整的任务成功 21/21，不完整的成功 2/39。

⚠️ 边界：这些数字来自指定测试集、检索预算和官方 AppWorld 智能体的下游检查，不能直接当作所有智能体任务的成功率。研究还指出两种较强方法错在不同位置：训练过的检索器常把缺失工具排在截断线后，层级方法则可能找到目标 API 却漏掉前置依赖。

一句话点评：我认为，多工具智能体首先该优化“所需工具是否齐全”，而不是拿单工具命中率证明它已经具备执行能力。

Flide：分支查询最高提速 9.5 倍

发生了什么：论文《Flide: Accelerating Decision Inference with Exact State Forking》提出一种面向决策模型的推理引擎。它针对的不是常见的逐词生成，而是智能体中需要沿不同分支快速作出类别选择的请求；传统生成式引擎处理这类请求，可能反复计算共同前缀，也可能改变输出概率。

关键细节：Flide 将请求的逻辑树与实际执行方式拆开，把分支放入一条扁平化词元流处理。其 ForkAttention 使用驻留在 GPU 上的索引，追踪标准注意力层与循环式 Gated DeltaNet 层中的分支依赖。作者称，在精确算术条件下，每个分支的结果与单独运行一次前向计算相同。分支拓扑通过 GPU 元数据表达，使不同请求组合能够共用一组预录制执行图；增长中的智能体历史也可从先前保存的检查点恢复。在公开混合模型和决策模型评测中，论文报告查询速度最高比 vLLM、SGLang 快 9.5 倍，并以 float32 参考结果比较输出分布差异。

⚠️ 边界：“精确”指论文给出的精确算术等价保证，不等于有限精度硬件上的结果逐位相同；作者因此另用总变差距离评估数值接近程度。9.5 倍是所述评测中的最高值，不能推作所有模型、分支形状和负载下的固定收益。

一句话点评：我更看重它把分支语义纳入执行设计，而不只是缩短延迟；决策服务若为速度改了概率，提速本身就不足以证明可用。

来源：arxiv.org

ZHA：树形索引让注意力走向次二次复杂度

发生了什么：论文《Subquadratic Attention with a Hierarchical Tree-Structured Indexer》提出 Zyphra Hierarchical Attention，简称 ZHA。作者要解决长上下文注意力的计算瓶颈：有些方法减少了实际参与计算的键，但查找这些键的索引过程本身仍可能随长度快速增长。

关键细节：ZHA 在 KV 缓存上构建一棵树，节点保存递归压缩的键摘要。新查询从树顶向下遍历，选出一小部分键，再执行最终注意力计算。作者称，逐步增加树深后，路由与最终注意力合计成本相对序列长度呈次线性增长，从而使整体注意力成本呈次二次、但仍高于线性的增长。论文表示，现有预训练模型可通过一个较短、使用数十亿词元的 KL 蒸馏阶段接入该方法。实验覆盖长上下文检索，以及推理、数学和智能体编码任务；作者还测试了最多 6 层的树形结构，并给出超过一百万词元时的性能模型。

⚠️ 边界：超过一百万词元时优于竞争方法，以及未来扩展到数亿或数十亿词元，涉及论文的性能建模与潜力判断；不能写成这些长度已经完成端到端部署。蒸馏阶段虽被作者称为较短，也不是完全免训练。

一句话点评：我认为这条路线的关键是把“寻找该看哪里”的开销一起算进去；只展示稀疏注意力计算量下降，仍可能漏掉真正的长上下文成本。

来源：arxiv.org

📰 推理和生成，改的是过程

LARC：GenEval 比 BAGEL 高 7 个百分点

发生了什么：论文《Latent Reasoning in Continuous Space for Unified Multimodal Models》提出 LARC，让统一多模态模型在连续隐藏状态中进行潜在推理。作者认为，语言推理通常发生在离散词元空间，而图像生成工作在连续空间；把语言式思维链直接接到图像生成前面，可能形成模态间的瓶颈。

关键细节：LARC 的训练分为两个阶段。第一阶段是课程式监督微调，逐步把词元层面的推理转换为潜在推理。第二阶段是信息增益强化学习，让模型在没有标准答案监督的条件下继续调整潜在推理。作者在多个文生图基准上报告，生成质量、对提示词的遵循程度和组合内容的准确性均有改善。在 GenEval 上，论文报告其成绩比 BAGEL 高 7 个百分点；在并行和顺序两种测试时扩展策略下，也观察到优于基于词元的生成方法的表现。

⚠️ 边界：这里的“潜在推理”不能直接等同于人能逐步审阅的文字推理，基准分数也不能单独证明模型为何画对了图。7 个百分点是与论文所列 BAGEL 对照的 GenEval 结果，不是对所有图像模型和任务的普遍提升。

一句话点评：我倾向于把它看作对推理载体的改造，而不是给画图模型补一段更长的文字解释；是否真有益处，要由生成结果和可控性共同检验。

来源：arxiv.org

CRoS：乱序思维步骤，检验推理有没有起作用

发生了什么：论文《CRoS: Causality Reward on Scrambled CoTs Improves Accuracy and Reasoning Faithfulness》提出一种思维链因果性指标，并把它用于奖励训练。作者针对的问题是：模型答对题，不意味着它写出的推理步骤真的影响了答案；而删除步骤或注入错误的旧式测试，又同时改变了步骤所包含的信息。

关键细节：CRoS 打乱推理步骤的顺序，但不改写每一步的内容，试图减少“信息被删掉了所以答案变了”的混淆。论文使用 Gemma-3-4B，在 Reasoning Gym 上训练，并在五个未见过的逻辑及游戏数据集上评估。作者报告，CRoS 的域外准确率为 46.8%，最强对照为 43.8%。CoT-Pass@K 从 K＝1 到 128 均优于对照，平均为 43.4% 对 41.4%。在提示承认指标上，论文给出的结果是 34.0% 对 20.2%。

⚠️ 边界：乱序保留了步骤文字，却不保证完全隔离其他变化：顺序本身可能影响语义连贯性，这正是该测试需要解释的因素。上述数字对应指定模型、训练任务和评估指标，不能据此断言所有任务中的思维链都已变得忠实。

一句话点评：我支持用“改变推理过程会不会改变答案”补充只看对错的奖励；但任何单一扰动测试，都不该被包装成推理真实性的最终证明。

来源：arxiv.org

DecisionRank：8B 重排模型在两项测试中提速

发生了什么：论文《DecisionRank: On-Policy Distillation for Decision-Model Rerankers》尝试把生成式大模型的排序知识，转给直接打分的决策模型。难点在于两者输出形式不同：教师给出文档 ID 的排序序列，学生则依据首个词元位置产生的分数决定名次。

关键细节：作者提出 item-space on-policy distillation，先按学生给出的文档分数排成一列，再把这列名单交给生成式教师。教师对学生实际形成的排序提供条件反馈，反馈再用于监督学生的分数。训练还结合了离线排序监督，评测覆盖 TREC DL、BEIR 和 BRIGHT 等一般及高推理需求的检索任务。论文称，在四项基准中，这种蒸馏目标均胜过所比较的其他训练目标。1.7B 参数的 DecisionRank 在 TREC DL19--23 上超过其 27B 生成式教师；8B 版本在 TREC DL 和 BRIGHT 上超过相应的生成式列表排序模型，速度分别快 24.5 倍和 16.7 倍。

⚠️ 边界：“超过教师”只对应论文列明的模型、数据集和指标，不表示小模型获得了教师全部能力。速度比较也限定在所述重排工作负载；检索、索引构建及整个应用的总耗时，并没有由这两个倍数完整表示。

一句话点评：我认为，把教师反馈对准学生自己排出的名单，比单纯模仿教师标准答案更切合重排场景；优势应以实际排序质量和延迟一起衡量。

来源：arxiv.org

DAMI：五类模型的检索准确率提高 5.29 至 16.71 个百分点

发生了什么：论文《DAMI: Dual-Axis Memory Initialization for Enhanced Long-Context Retrieval in Gated Linear Attention》研究门控线性注意力的长文本检索能力。线性注意力的计算成本可随序列长度线性增长，但有限状态记忆可能使远处信息难以保留；作者把注意力放在训练开始前如何设置记忆参数。

关键细节：论文指出，在受控 Gated DeltaNet 实验中，门控参数 A_log 与 dt_bias 经过训练后仍与初始值高度相关。DAMI 因而联合配置这两个参数：不同注意力头采用几何分布的时间尺度，以覆盖不同检索距离；不同层采用“低—高—低”的输入敏感度配置。方法使用少量激活样本校准实现，不增加可训练参数。作者在 GDN、KDA、GDN2、Mamba-2、RWKV-7 上测试，相较各自随机初始化基线，RULER 风格检索任务的平均准确率提高 5.29 至 16.71 个百分点。语言建模、常识推理和 2K 真实世界检索表现，论文称与对应基线大体相当。

⚠️ 边界：提升范围对应 RULER 风格检索与所列模型，不能概括为所有长上下文任务都有同等增益。“不增加可训练参数”也不等于现成模型无需重新训练即可获得结果：该方法针对的是训练前初始化，并包含实施时的校准步骤。

一句话点评：我认为这说明记忆能力不只取决于注意力结构，训练起点也可能决定模型能把信息留多远；但检索收益仍须与其他任务表现一起看。

来源：arxiv.org

PersonaChatBench：20 个模型面对不同用户，成绩不一致

发生了什么：论文《PersonaChatBench: Evaluating Chat Assistants with Diverse Simulated Users》提出一种聊天助手评测方法：保持任务相同，只改变模拟用户的需求、偏好及交流方式。作者认为，若测试里总是同一种配合度高的用户，汇总成绩可能掩盖助手服务不同人群时的差异。

关键细节：框架给每名模拟用户一张不向被测助手公开的角色卡，写明其个人需求及互动行为。论文在六个领域评估 20 个语言模型，并分别衡量原任务完成情况、用户已表达需求的满足程度，以及模拟器本身是否忠实呈现设定。作者报告，同一任务在不同用户条件下，任务表现与需求满足程度都会变化。任务本身做得好，不保证用户的具体需求也得到满足；不同模型在满足需求方面的相对强弱，也不会在各领域保持一致。该设计因此能把被平均分数遮住的差异单独呈现出来。

⚠️ 边界：角色卡驱动的是模拟用户，不是对真实用户群体的抽样调查。模拟器忠实度被单列评估，正说明若模拟用户没有按设定行动，测得的差异就可能混入模拟器误差；不能把基准上的角色表现直接当作现实人群满意度。

一句话点评：我认为助手评测不该只问“任务做完没有”，还该问“为谁做完、是否按那个人的需求做完”；不过模拟用户不能替代真实使用反馈。

来源：arxiv.org

aFMLM：一次前向生成，也把词元顺序算进去

发生了什么：论文《Asynchronous Flow Map Language Models》研究单步并行语言生成中的预测顺序。自回归模型与掩码扩散模型可以在多步生成过程中利用顺序；如果所有词元只用一次前向计算同时生成，怎样保留顺序带来的帮助，就成为作者要解决的问题。

关键细节：aFMLM 通过异步流的映射学习，把预测顺序编码进单步模型。异步流为每个词元设置时间安排，控制它相对于其他词元的去噪进度。作者讨论了预先指定的安排，也讨论了能够随状态调整、由模型学习的安排，并给出相应的流映射蒸馏方法。训练后的模型把这种先后关系纳入内部隐藏计算，生成时仍可通过一次前向计算输出全部词元。论文报告，在数独求解以及针对 GSM8K 数学应用题的代码生成任务上，模型取得单步生成设定中的新最佳表现。

⚠️ 边界：“一次前向”描述的是该模型生成词元的方式，不表示训练或蒸馏只需一步，也不自动等于整体系统延迟最低。论文所列最佳表现限定在单步设定和所述任务，不能推出开放式写作、一般聊天或所有代码任务已有同样收益。

一句话点评：我认为它抓住了并行生成的核心矛盾：计算可以同时发生，任务所需的依赖顺序却未必能省掉；把顺序内化，是比直接忽略它更有说服力的做法。

来源：arxiv.org
