LARC：连续隐状态推理让图像生成在 GenEval 上领先 BAGEL 7 个百分点

发生了什么：论文提出 LARC，试图让统一多模态模型在生成图像时真正用上推理，而不是先写出一串文字推理，再把它交给图像生成过程。作者认为，现有方法难以继承语言模型的测试时扩展能力和细粒度控制能力，症结在于文字推理使用离散 token，图像生成却运行在连续空间。

关键细节：LARC 将推理放到连续隐状态中，以缓解逐 token 表达造成的瓶颈。训练分为前后衔接的两个阶段：课程式监督微调先逐步把 token 级推理转为潜在推理，随后用信息增益强化学习，在没有真实答案监督的条件下继续演化推理过程。这样的安排不是直接丢掉语言推理，而是先借它建立路径，再把推理迁移到更接近图像生成的表示中。作者在多种文生图基准上报告，生成质量、遵循提示词和组合关系的还原均有改善。在 GenEval 上，LARC 比 BAGEL 高 7 个百分点；并行与顺序两种测试时扩展策略下，它也优于基于 token 的生成方式。

⚠️ 边界：摘要没有给出各项基准的逐项成绩，也没有说明不同算力预算下的质量—成本曲线，因此不能把 GenEval 的差距直接当成所有图像任务的差距。「没有真实答案监督」指后续强化学习阶段，不等于整个方法不需要监督数据；前一阶段仍是监督微调。测试时扩展有效，也不能单凭摘要判断增加计算量何时开始不划算。

一句话点评：我认为这篇工作的关键不是让模型「想得更多」，而是让推理所用的表示更贴近生成对象；若这一点能在更多任务上成立，文字思维链就不再是多模态推理的默认接口。

来源：arxiv.org

Flide：精确分叉状态，决策查询最高比 vLLM、SGLang 快 9.5 倍

发生了什么：面向 Jev 一类直接输出类别判断的决策模型，论文提出推理引擎 Flide。问题不在于怎样生成更长的文字，而在于同一代理历史上出现多个待判断分支时，现有生成式引擎要么反复计算共同前缀，要么使输出概率偏离原本的独立执行结果。

关键细节：Flide 将请求的逻辑树与实际执行解耦，把分支安排进一条扁平的 token 流。其 ForkAttention 利用驻留 GPU 的索引追踪分支依赖，覆盖普通注意力以及循环式 Gated DeltaNet 层，而非只处理一种网络部件。论文给出的精确性条件是「在精确算术下」：每条查询分支应与单独做一次前向传播得到相同结果。分支拓扑写入 GPU 元数据后，不同请求组合可以复用一组紧凑的预录制执行图；不断增长的代理历史也能从先前保存的检查点接续。公开混合模型和决策模型上的评估显示，查询回答最高比 vLLM、SGLang 快 9.5 倍，同时其输出概率与 float32 参考结果的总变差距离最接近。

⚠️ 边界：「精确」首先是数学执行路径的保证，不应误读为不同 GPU 实际浮点运算逐位相同；论文也因此另用概率距离检验数值结果。「最高快 9.5 倍」是评估中的上限，不是每种请求混合、模型或历史长度都能得到的固定加速。它解决的是决策推理的执行成本，不直接证明决策本身更正确。

一句话点评：我更看重它把分叉语义做进执行引擎，而不是单次测速；对反复沿同一历史试探选项的代理，这比单纯加快文字生成更对症。

来源：arxiv.org

DecisionRank：1.7B 决策模型在 TREC DL19--23 超过 27B 生成式教师

发生了什么：DecisionRank 要把生成式语言模型的排序知识交给直接打分的决策模型。两者原先并不好对齐：教师用一串文档 ID 表达名次，学生却在首 token 位置给各文档打分，单纯模仿教师输出无法直接教会学生怎样调整自己的分数。

关键细节：论文的「条目空间在策略蒸馏」先把学生当前给出的文档分数排序，形成学生自己的候选名次，再将这份名单送给生成式教师取得条件反馈。反馈直接监督产生该名单的分数，因此训练对象不是教师预先写好的静态排序，而是学生实际可能做出的排序。方法还结合离线排序监督；作者在 TREC DL、BEIR、BRIGHT 等一般及高推理需求检索基准上报告领先表现，且在四个基准中，这种蒸馏目标均优于所比较的其他训练目标。即使只有 1.7B 参数，DecisionRank 在 TREC DL19--23 也超过 27B 生成式教师；8B 版本超过对应的生成式列表排序模型，在 TREC DL 快 24.5 倍，在 BRIGHT 快 16.7 倍。

⚠️ 边界：这些速度数字比较的是所述决策模型与生成式列表排序对应方案，不能外推为整个检索系统的端到端延迟。小模型超过教师也有明确的基准范围，不能解释为它在所有排序任务上都更强。离线监督仍是训练的一部分，「在策略」描述的是学生排序进入教师反馈的过程，并非训练完全摆脱已有排序数据。

一句话点评：我认为真正可复用的思路是让教师评价学生已经排出的名单；当部署目标是快速选项打分时，围绕学生自己的错误来蒸馏，比照搬教师的生成格式更合理。

来源：arxiv.org

ZHA：树形索引让注意力低于平方增长，测试树深达 6 层

发生了什么：长上下文注意力的平方级开销，既可能出现在最终计算中，也可能被寻找稀疏位置的索引过程重新带回来。论文提出 Zyphra Hierarchical Attention（ZHA），用层级树索引选择要看的历史键，目标是让索引与最终注意力的合计成本都随上下文更缓慢地增长。

关键细节：ZHA 在 KV 缓存上递归压缩键，形成树状摘要；后续查询从树顶向下遍历，最后只取一部分键执行注意力。树深随序列增长而迭代增加，是它避免固定层级下检索成本失控的关键。论文称，计入路由和最终注意力后，单次查询的相关成本随序列长度呈次线性增长，总体注意力成本则高于线性、低于平方。它可以通过覆盖数十亿 token 的短期 KL 蒸馏，应用到已有预训练模型，而不是要求从头训练。作者报告其在长上下文检索、推理、数学与代理编程评估中维持表现，对包括深至 6 层的树形结构也较稳健；性能模型显示，超过 100 万 token 时优势明显。

⚠️ 边界：将有效上下文延伸到数亿或数十亿 token，文中表述是潜力，不能当成已经完成的模型实测。超过 100 万 token 的优势也有性能模型支撑，需与具体硬件和任务上的运行结果区分。稀疏选键依赖压缩摘要和路由；若关键信息未被选中，「次平方」并不能自动保证回答正确。

一句话点评：我认为它抓住了稀疏注意力常被忽略的账本：只有把「找哪些键」也算进去，长上下文的扩展性才有说服力。

来源：arxiv.org

发生了什么：Knowledge Layer Model（KLM）提出一种与具体实现无关的推理记录规范，让审阅者能检查答案所记录的依据、证据关系、版本化认识判断及明确的未知项。Nage AI OS 的知识与证据架构 SEDIM 被列为参考实现；论文讨论的是 KLM v0.3，并明确将内部实验与端到端验证分开。

CRoS：打乱推理步骤顺序，未见数据集准确率达 46.8%

发生了什么：通常的可验证奖励强化学习奖励最终答案，却不能保证思维链真的参与得出答案。CRoS 尝试把「推理是否起因果作用」纳入奖励，同时修正已有测试的一处混淆：删除步骤或注入错误既改变推理流程，也改变了步骤携带的信息。

关键细节：CRoS 不删改每一步的内容，而是打乱推理步骤的顺序，再观察答案对这种扰动的反应，以减少信息被同时改变带来的干扰。作者指出，若把有混淆的因果分数直接用于训练，模型可能转向信息量更少的思维链，并减少探索及自我纠错。在 Reasoning Gym 上以 Gemma-3-4B 评估时，CRoS 在五个未见过的逻辑与游戏数据集上取得 46.8% 准确率，最强对照为 43.8%。其 CoT-Pass@K 从 K=1 到 128 持续优于对照，平均为 43.4% 对 41.4%；提示承认分数为 34.0% 对 20.2%。论文据此分别报告了分布外答题、思维链质量及忠实度的改善，而非只看最终答对多少。

⚠️ 边界：保留每一步的文字信息，不等于打乱顺序后仍保留原来的推理含义；步骤之间若有严格依赖，顺序变化本来就会破坏可执行性。因此，这项指标减少的是「删改内容」带来的混淆，不能单凭它证明模型内部的完整因果机制。所列成绩也受所用模型、任务与提示承认测法限制。

一句话点评：我倾向把 CRoS 看成更干净的训练信号，而不是思维链真实性的终局裁判；它最有力的证据，是多项指标一起改善，而非单个因果分数升高。

多工具检索：工具集完整时 21/21 成功，不完整时仅 2/39

发生了什么：代理执行复杂请求时，只找对「最相关的一个工具」可能仍然失败，因为它还需要所有前置工具。论文比较不同检索结构，不只问所需工具能否排上榜，更问执行请求所需的整套工具能否同时进入候选名单，以及为此要付出多少调用、token 和等待时间。

关键细节：评估使用带专家依赖标签的 345 条 AppWorld 查询，以及覆盖 257 个 MCP 工具的 103 项 MCP-Bench 任务。指标 completeness@k 计算的是前 k 个结果包含全部必需工具的查询占比，而非单个工具的命中率。对 7,961 条 ToolRet 查询的分析发现，取前 10 个结果时，单目标查询的完整率为 .58 至 .67，需要至少四个目标时仅为 .08 至 .17；检索器在两类查询上的名次还会颠倒。未用测试集训练、每次查询最多调用一次语言模型的受测结构，在 AppWorld 的 k=16 条件下均未超过 10%。另有集合级检索器用 75 至 90 条域内查询训练后，在两套测试上分别达到 .33 和 .58；语言模型导航的层级结构达到 .30 和 .40，却需要中位数 31 至 38 次模型调用、每次查询约五分钟。

⚠️ 边界：训练过的集合级检索器与未在测试集训练的方法，不应只按完整率作无条件胜负比较；层级结构的完整率也必须连同调用成本看。两者漏工具的方式不同：前者常把缺项排在截断线下方，后者会找到目标 API 却停在收集前置依赖之前。官方 AppWorld 代理的后续检查中，完整工具集对应 21/21 次成功，不完整集对应 2/39 次成功；这说明完整性重要，但不保证换个任务或代理仍能全部成功。

一句话点评：我认为代理工具检索应把「凑齐可执行工具集」列为主指标；单工具召回率再漂亮，也掩盖不了缺一个前置工具就无法开工的问题。

  • DAMI：不增加可训练参数，改善门控线性注意力的长距检索。 论文观察到 Gated DeltaNet 中影响记忆衰减的 A_log、dt_bias 在训练后仍与初值高度相关，于是训练前同时配置它们：在不同头之间安排几何级数式记忆时程，在层间安排低—高—低的输入敏感度，再用少量激活样本校准实现。在 GDN、KDA、GDN2、Mamba-2、RWKV-7 上，相对各自随机初始化基线，平均 RULER 式检索准确率提高 5.29 至 16.71 个百分点；语言建模等表现大体相当。一句话点评：我认为这比训练后补救记忆不足更直接，但摘要支持的是所测长距检索改善，并非所有长上下文任务都同步受益。来源：arxiv.org
