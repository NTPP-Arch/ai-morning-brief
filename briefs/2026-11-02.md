## 📰 模型与生成

### 连续隐状态推理：GenEval 比 BAGEL 高 7 个百分点

**发生了什么**  
《Latent Reasoning in Continuous Space for Unified Multimodal Models》提出 LARC，让统一多模态模型在连续隐状态中进行推理，而不是先把推理全部写成离散文字，再交给图像生成环节。论文针对的是一个具体断点：语言模型中的思维链能力，未必能直接转化为图像生成时的控制能力。

**关键细节**  
训练分为课程式监督微调和信息增益强化学习两个阶段。前一阶段逐步把 token 层面的推理转为潜在推理，后一阶段不依赖真实答案监督来继续优化。论文称，多项文生图测试中的生成质量、提示词遵循度和组合忠实度均有改善。在 GenEval 上，作者报告成绩比 BAGEL 高 7 个百分点。并行和顺序两种测试时扩展策略下，论文都报告了优于基于 token 的生成方式的结果。

**⚠️ 边界**  
这些是论文作者报告的实验结果，不等于已在所有图像任务或实际产品中验证。素材没有给出各项测试的完整分数、计算开销或独立复现结果；7 个百分点也仅对应文中所述的 GenEval 对比，不能外推为所有指标的提升。

**一句话点评**  
我更看重它把推理位置从“可读文字”移向生成过程本身；若收益离不开昂贵的测试时计算，实际部署价值仍需另算。

### 树状索引注意力：瞄准超过百万 token 的成本

**发生了什么**  
《Subquadratic Attention with a Hierarchical Tree-Structured Indexer》提出 Zyphra Hierarchical Attention，简称 ZHA。它要解决的不只是标准注意力随序列变长而增长的计算量，还包括某些稀疏注意力方案中、负责挑选信息的索引器自身也可能过于昂贵的问题。

**关键细节**  
ZHA 在 KV 缓存上构造递归压缩的键摘要树，让后续查询从树顶向下寻找需要读取的少量键。作者称，随着树深逐步增长，路由与最终注意力合计的成本可低于序列长度的线性增长，因此注意力整体呈次二次、但高于线性的扩展趋势。论文表示，已有预训练模型可通过在数十亿 token 上进行短阶段 KL 蒸馏来适配。测试覆盖长上下文检索，以及推理、数学和智能体编码任务。作者还报告了最高六层深树的稳健性，并用性能模型讨论超过百万 token 的情形。

**⚠️ 边界**  
“数亿或数十亿 token 的有效上下文”在素材中属于潜力判断，不是已经完成的部署结果。超过百万 token 的优势部分来自论文性能模型；素材未给出不同硬件、内存预算和实际工作负载下的完整对照数据。

**一句话点评**  
我认为把索引成本一起算进去，比只展示稀疏读取速度更有说服力；但超长上下文的潜力还不能当成现成容量。

## 📰 智能体与检索

### Flide：决策查询最高提速 9.5 倍

**发生了什么**  
《Flide: Accelerating Decision Inference with Exact State Forking》提出面向决策模型的推理引擎 Flide。此类模型直接处理类别选择等任务；论文认为，沿用生成式模型的推理引擎，可能反复计算分支共享的前缀，或改变原本应有的输出概率。

**关键细节**  
Flide 将决策请求的逻辑树与实际执行方式分开，把执行组织到一条扁平 token 流中。其 ForkAttention 使用驻留 GPU 的索引处理请求依赖，覆盖常规注意力和循环式 Gated DeltaNet 层。论文称，在精确算术条件下，每个查询分支的计算与单独前向运行一致。分支拓扑写入 GPU 元数据后，不同请求组合可以复用一组预先记录的执行图；增长中的智能体历史也可从先前保存的检查点继续。公开混合模型与决策模型评测中，作者报告查询速度相对 vLLM 和 SGLang 最高提升 9.5 倍。

**⚠️ 边界**  
“精确”指论文所述的精确算术保证；实际数值结果仍需看浮点实现，因此作者另以 float32 参考结果比较概率差异。9.5 倍是报告的最高速度提升，不代表每种模型、请求组合或设备都能达到。

**一句话点评**  
我认为它抓住了决策型智能体的真实瓶颈：共享状态若能准确复用，延迟收益才不必以扭曲分支概率为代价。

### 多工具检索：找齐工具的任务成功 21/21

**发生了什么**  
《Completeness and Cost of Retrieval Structures for Multi-Tool Requests in LLM Agents》把问题从“检索到一个相关工具”改为“检索齐完成任务所需的全部工具”。作者比较多种工具检索结构，并同时计入检索阶段的大模型调用、token 和延迟成本。

**关键细节**  
研究使用带专家依赖标注的 345 条 AppWorld 查询，以及涉及 257 个 MCP 工具的 103 项 MCP-Bench 任务。另对 7,961 条 ToolRet 查询的分析显示，取前十个结果时，单目标查询的完整率为 0.58 至 0.67；需要四个或更多目标时降至 0.08 至 0.17。在 AppWorld 中，不依靠测试集训练且每次至多调用一次大模型的受测结构，取前 16 个结果时完整率均未超过 10%。一个经过 75 至 90 条域内查询训练的集合级检索器，在两个测试集上的完整率分别为 0.33 和 0.58。下游检查中，工具集完整的任务成功 21/21，工具不完整的任务成功 2/39。

**⚠️ 边界**  
这些比例对应特定测试集、候选数量和检索结构，不能视作所有智能体的通用成功率。另一种表现较好的大模型导航式层级结构，每次查询中位数需调用 31 至 38 次大模型、耗时约五分钟；完整率不能脱离成本单独比较。

**一句话点评**  
我认为多工具智能体应先考核“依赖是否找齐”，再谈单项工具排名；漏掉一个前置工具，后续推理再强也难补救。

## 📰 评测与推理

### CRoS：未见数据准确率 46.8%，对照为 43.8%

**发生了什么**  
《CRoS: Causality Reward on Scrambled CoTs Improves Accuracy and Reasoning Faithfulness》提出一种评估并奖励思维链因果作用的方法。作者指出，只奖励最终答案正确，并不能证明模型确实使用了写出的推理过程；删除步骤或注入错误等旧式扰动，又会同时改变步骤中的信息。

**关键细节**  
CRoS 的做法是打乱推理步骤的顺序，但保留每一步的内容，以减少信息变化带来的混淆。论文在 Reasoning Gym 上使用 Gemma-3-4B 开展实验。五组未见过的逻辑与游戏数据中，CRoS 的准确率为 46.8%，最强对照为 43.8%。在 K 从 1 到 128 的 CoT-Pass@K 比较中，其平均表现为 43.4%，对照为 41.4%。论文报告的提示承认得分为 34.0%，对照为 20.2%，并称推理质量与忠实度也有改善。

**⚠️ 边界**  
打乱顺序比删除内容更能控制信息变化，但不能单凭这一操作证明所有推理步骤都真实导致了答案。上述差距来自论文给定的模型、任务和指标；素材没有提供更大模型或实际复杂任务中的复现结果。

**一句话点评**  
我赞成把“答案对了”与“过程起了作用”分开训练；不过因果指标本身仍须接受比单一扰动更严格的检验。

### PersonaChatBench：20 个模型，同题换人测

**发生了什么**  
《PersonaChatBench: Evaluating Chat Assistants with Diverse Simulated Users》提出一种对话助手评测框架：保持底层任务不变，让需求、偏好和交流方式不同的模拟用户分别提出请求。它要识别的是，助手在同一任务上表现稳定时，是否也能稳定满足不同人的具体需求。

**关键细节**  
每位模拟用户由一张不向被测助手公开的人设卡引导，人设卡规定其需求与互动行为。研究评测了 20 个语言模型，任务覆盖六个领域。评测将原生任务结果、明确表达的个人需求是否得到满足，以及模拟器自身的保真度分开记录。作者报告，任务表现和需求满足程度都会随人设及领域变化。某个模型能把任务完成得好，并不意味着它同时满足了用户的个别需要；模型之间的相对强弱也不会在所有领域保持一致。

**⚠️ 边界**  
这里的“用户”是模拟器扮演的，不等同于真实人群的长期使用体验。素材没有给出各模型逐项排名或不同人设的样本分布；模拟器保真度被单列评估，也提示不能把人设差异全部归因于被测助手。

**一句话点评**  
我认为助手评测不能再只报一个总体任务分数；同题换人后暴露的落差，才更接近产品需要处理的适配问题。
